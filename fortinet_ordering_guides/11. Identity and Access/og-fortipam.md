Privileged Access is defined as access to an account with privileges beyond those
of regular accounts, typically in keeping with roles such as IT Managers and System
Administrators. Examples of privileged access include Firewall & Network Administrators,
Windows Domain/Enterprise admin users, etc.
Importantly Privileged Account attacks remain a high-profile attack vector, and in many
instances, detection alone is measured in hundreds of days, with recovery taking
significantly longer.
FortiPAM protects privileged accounts against credential theft and privilege abuse
by managing account credentials, controlling privileged user access, and monitoring
privileged activity.
FortiPAM is Fortinet’s purpose-built Privileged Access Management Solution, built on
the firm foundations of FortiOS, delivers a richly featured, and robustly secured solution.
Offering broad capabilities in Secret Management, Session handling & Controls, Zero
Trust Network Access, and User management. Additionally, FortiPAM lends itself to
distributed & sequestered environments, seamlessly supporting multiple geographies.
Importantly, FortiPAM offers flexible purchasing options - this ordering guide is designed
to help you choose the right solution.

License Ordering Information
Licensing is spread across three main product areas:
• Hardware Units & Services
• User-license Upgrade for Hardware Models
• VM appliances, each offering a set quantity of named users.
• Here, there are no restrictions on user sessions – only the number of created users.
• MOQ 5 seats
• VM appliances, each offering a set quantity of concurrent logon sessions
• In this model, there are no restrictions on the number of created users, only the number of users logged into FortiPAM at
any given time. Note that if a single user were to login to FortiPAM from two different terminals, this would count as two
login sessions.
• MOQ 1 Concurrent session
One point of note is that each of these are mutually exclusive and cannot interoperate. In a configuration where HA will be
deployed, each HA node must be from the same license type.

BOM Examples & User Licensing
BOM requirements differ based on whether the user wishes to purchase Hardware models, or VM instances.
Each of the hardware models ship with a predefined quantity of users; 1000G shipping with 50 users by default, the 3000G
shipping with 100. User upgrade packs exist for each, in addition to subscription packs for AV, DLP & FortiCare Premium Support.
Importantly, User subscriptions on the hardware platforms are perpetual, whereas users on the VM platforms fall under a
subscription model, with 1, 3, and 5 year subscriptions available.

depends on the platform:
• FortiPAM-VM: Maximum 3000 enabled users

FortiPAM in configuration HA
FortiPAM fully supports an HA. The behavior of HA does differ slightly across Hardware and VM
For VM users only, with the release of FortiPAM 1.5.0, Users are now ‘Pooled’ across the HA and DR appliances.
This means that, if a customer buys 25 users on the HA primary, and 5 users on the DR, the customer will have a collective pool
of 30 users. In an HA ‘event’, that pool of users will become enabled on the DR appliance with no user input required.
Thus, if a customer wishes to setup FortiPAM in an HA environment, a BOM might look like this:
VM
User requirement: 30 FortiPAM-VM users, in an HA Configuration
BOM: 25 x FC3-10-PAVUL-591-02-DD, 5 x FC1-10-PAVUL-591-02-DD
User requirement: 6 FortiPAM-VM Concurrent sessions, in an HA Configuration, for 5 years
BOM: 3 x FC1-10-PAVUL-1303-02-60, 3 x FC1-10-PAVUL-1303-02-60
Hardware
User requirement: 50 users on a FortiPAM-1000G, in an HA configuration, each with DLP enabled.
BOM: 2 x FPA-1000G, 1 x FC-10-PA1KG-681-02-12, 1 x FC-10-PA1KG-681-02-12

This approach facilitates a robust security posture, leaning into the full scope of ZTNA tags.

In cases where FortiClient install is impossible, FortiPAM offers a feature-rich browser extension. Alongside the FortiClient Agent
on the Product Downloads page, users may additionally locate their preferred browser extension.
