Sizing and Packaging Guidance
Start with Outcome, Then Scale
The original guide moves quickly into SKU detail. Before showing SKUs, give sales a short packaging framework so they know
what they are trying to configure. The goal is to help them determine whether the customer needs a base deployment only, a
scaled deployment, or a fully expanded dynamic analysis environment. The original guide provides VM counts, Cloud VM ranges,
and license dependency detail that is important later in the quoting process.
How to Size the Deployment
Start with file volume, operational model, and data handling requirements.
CUSTOMER PROFILE RECOMMENDED STARTING POINT NOTES
Existing FortiGate customer, simple deployment SaaS Base deployment
Customer wants dedicated hosted service PaaS Scaled deployment
Customer wants cloud control FSA-VM Scaled deployment
Mid-size on-prem deployment 500G Scaled / Mid-size SOC deployment
Enterprise deployment 1500G Scaled / Enterprise SOC deployment
High-throughput SOC / large enterprise 3000G High throughput / Enterprise SOC deployment
The environment scales driven by: Base platform selection, Subscription tier, Universal VM capacity, Microsoft Windows / Office
licensing for nested VMs and Optional Xloud VM expansion in supported models
Quoting List
Use this checklist to avoid the most common ordering mistakes:
1 – Every deployment starts with a base platform
That may be: SaaS service, PaaS bundle, FSA-VM, Hardware appliance (500G / 1500G / 3000G)
2 – Add the right subscription
Choose:
• Standard Sandbox Threat Intelligence for baseline detection. Includes FortiGuard Essentials and Sandbox Essentials.
• Advanced AI Subscription for enhanced protection and phishing / IOC capabilities Includes FortiGuard Essentials, Sandbox
Essentials, and Advanced Sandbox capabilities.
3 – Add VM Capacity for Sandbox detonation (Dynamic Scan)
Use Universal VMs to scale sandbox analysis capacity.
• Universal VMs can be used as:
• Nested VMs (run on appliance/VM → requires Microsoft licenses)
• Cloud VMs (Fortinet-hosted → no Microsoft licenses required)
• When to add more VMs: High file submission volume, Need faster analysis turnaround, Large SOC or enterprise environments
• Scaling guidance:
• Start with included VM capacity per model
• Add Universal VM licenses as needed
• Expand to Cloud VMs for additional throughput without licensing overhead
Refer to the Ordering Summary table for per-model VM limits
4 – Add Microsoft licenses for nested VMs
Only for Nested VMs on VM/HW Appliance. Nested VMs require activated Windows and Office licenses. Whereas, SaaS and
Cloud VMs are pre-licensed.
5 – Treat each FortiSandbox unit separately
The seat-based licenses such as VM expansion should be listed separately per unit to avoid unintended stacking and
registration issues.

Frequently Asked Questions
1. Getting Started & Deployment
What is the minimum deployment to run FortiSandbox?
You can start small. Start with SaaS or a base appliance, then scale as needed.
• SaaS → No infrastructure required (fastest path)
• Appliance → Comes with default VMs and licenses
• Basic subscription → Enough for initial protection and updates
What’s the best way to size a deployment?
Start with estimates, validate with real data. If sizing is unclear → position a POC to de-risk the decision.
Two approaches:
• Estimate-based → Use Fortinet data from similar customers
• POC-based (ideal) → Measure actual file submission rates
How do I scale if the customer has high file volume?
Performance concerns are solvable—don’t let them block the deal.
• Add more VMs (nested or cloud)
• Scale up to larger appliances (1500G / 3000G)
• Use clustering (up to 99 units) for very large environments
What is a hybrid VM deployment?
A combination of:
• Local (nested) VMs → run on the appliance
• Cloud VMs → run in Fortinet-hosted infrastructure
Used to increase dynamic analysis throughput. Position hybrid when customers want performance + flexibility.
2. Features & Capabilities
Do I need IL MPS to use inline blocking?
Inline prevention behavior differs by deployment model. On SaaS, the IL MPS is required. On SOC and Advanced deployment,
Inline blocking is a feature built into FortiSandbox (v5.0+).
What is the Antivirus Extended Database?
Extended DB = higher detection coverage, especially for older threats.
Default AV uses a smaller active database
Extended DB includes full coverage (active + legacy malware)
Can FortiSandbox integrate with non-Fortinet tools?
Yes. This is not a closed ecosystem—works in mixed environments.
Supports:
• ICAP
• JSON RPC APIs

3. Licensing & VM Strategy
Do I need Microsoft licenses?
Depends on deployment type:
Scenario License Required
Nested VMs (on appliance/VM) Yes
Cloud VMs (Fortinet-hosted) No
How many Microsoft licenses are needed?
• 1 Windows license per VM (or clone)
• 1 Office license per ~5 Windows VMs
What type of Microsoft licenses are provided?
• Retail-type Windows licenses (validated by Fortinet)
• Compatible with FortiSandbox environments
No special licensing complexity—standard Microsoft model.
Can customers bring their own licenses (BYOL)?
Yes (via Custom VM option). But:
• Customer must manage compliance and activation
Use BYOL only when customers have strong licensing and application requirements.
What is a Universal VM?
A flexible VM pool that can be used as:
• Nested VM (on appliance)
• Cloud VM (Fortinet-hosted)
• Hybrid (mix of both)
Universal VM = flexibility + scalability
How many Universal VMs should I recommend?
Depends on:
• Appliance limits
• Cloud VM capacity
Sell based on throughput needs, not arbitrary VM counts. Example:
• FSA-1500G → up to 120 total VMs (mix of local + cloud)
What happens to VM count licenses after upgrading to v5.0?
• Existing licenses are automatically retained
• Converted into a pooled VM capacity model
Upgrades are non-disruptive from a licensing perspective.
Can customers upgrade their FortiSandbox later?
Yes.
• Supports upgrades (e.g., VMS tiers)
• Supports co-term licensing for simplified renewals
